# Craftly Supabase — المرحلة الأولى: قاعدة البيانات والصلاحيات

## الحالة الحالية

ملف `migrations/202609270001_craftly.sql` وجد وجربناه محلياً بـPostgreSQL/PGlite مع بدائل لاختبار auth/storage. **ما تطبقش تلقائياً على مشروع Supabase ديالك.** اختبارات التخزين كتختبر سياسات SQL، ماشي خدمة Storage الفعلية أو روابط التحميل الموقعة عن بعد.

**التطبيقين الحاليين مازال كيستعملو Express. هاد السكريبت بوحدو ما كيحوّلهمش لـSupabase.** الربط الجديد وإعادة بناء APK مرحلة منفصلة لاحقة. ما تدخلش عنوان Supabase في خانة Express server address ديال APK القديم.

## دابا شنو تدير فالهاتف؟

1. افتح [ملف SQL](migrations/202609270001_craftly.sql) على GitHub.
2. اضغط **Raw** (أو **⋯ → View raw** حسب الواجهة)، وانسخ المحتوى كامل. خاص يبدأ بـ`-- Craftly / Supabase setup v1` وينتهي بـ`select 'Craftly setup complete...`.
3. رجع لـSupabase → **SQL Editor** → الاستعلام الفارغ اللي حلّيتي.
4. ألصق الملف كامل واضغط **Run**. ما تختارش غير شي سطر منو.
5. انتظر النتيجة:

```text
Craftly setup complete. No admin account has been assigned yet.
```

إذا بان خطأ، صيفط لينا نص الخطأ أو صورة النتيجة بلا مفاتيح سرية. ما تبدلش سياسات الحماية عشوائياً وما توقفش RLS باش تحاول تصلح الاتصال.

## شنو كينشئ؟

- `craftly_profiles`: الاسم والدور. دور الأدمن ما قابلش للتعديل من التطبيق أو بيانات التسجيل.
- `craftly_mods`: الكتالوج؛ الزوار كيشوفو المنشور فقط، غير الأدمن كيكتب ويحذف.
- `craftly_favorites`: المفضلة الخاصة بكل مستخدم.
- `craftly_ratings`: تقييم واحد لكل مستخدم ومود. العامة كيشوفو المتوسط والعدد فقط.
- `craftly_downloads`: طلبات التحميل الخاصة بكل مستخدم، مرة فالإحصاء لكل مستخدم/مود؛ ماشي تأكيد اكتمال نقل الملف.
- `craftly-covers`: صور علنية، حتى 8 MiB. ما ترفعش فيها صور سرية.
- `craftly-packages`: ملفات خاصة، حتى 50 MiB. المستخدم المسجل يقدر يطلب رابطاً موقعاً لملف مرتبط بمود منشور فقط.

القيم بالبايت: الصور `8388608` والملفات `52428800`. رفع الحزم مقصور على الأدمن وامتدادات Bedrock؛ هذا لا يقوم بفحص البرمجيات الخبيثة أو ضمان صلاحية حزمة Minecraft. خاص غير حزم عندك الحق تنشرها ومجربة فاللعبة.

المسارات تكون مثل `UUID/filename.mcpack`. تغطية الصورة والملف كتربط بسجل المود. حذف السجل ما كيحذفش Storage objects بوحدو؛ الربط الجديد خاصو ينظفهم باستعمال Storage API. ما تحذفش rows من `storage.objects` يدوياً.

## حساب الأدمن — ما تديرش هاد الخطوة قبل ما يكون الحساب موجود

السكريبت الأول **ما كيعطي حتى واحد دور الأدمن تلقائياً**. من بعد التسجيل بـSupabase Auth واختيار حسابك، المالك يقدر ينفذ من SQL Editor:

```sql
update public.craftly_profiles
set role = 'admin'
where id = (
  select id from auth.users
  where lower(email) = lower('PUT_YOUR_OWN_EMAIL_HERE')
)
returning id, display_name, role;
```

بدّل البريد ببريد حسابك أنت فقط. إلى رجع صفر نتائج، الحساب ما موجودش بعد. ما تحتاج لا service-role key لا كلمة مرور قاعدة البيانات فالمحادثة أو APK. اسمح فقط للناس الموثوقين بالوصول إلى Supabase Dashboard/SQL Editor.

## ملاحظات الأمان

- السكريبت خاص بمشروع Craftly جديد أو بلا سياسات قديمة كتسمح بالولوج العام إلى `storage.objects`. سياسات PostgreSQL المتساهلة كتتجمع بـOR؛ سياسات مضافة يدوياً من قبل تقدر توسع الولوج. راجعها إذا المشروع ماشي جديد.
- إعادة تشغيل نفس النسخة لا تحذف الحسابات أو المودات. كتجدد فقط وظائف وسياسات Craftly وإعدادات bucket الخاصة به.
- الملفات داخل public cover bucket تبقى علنية حتى إلا كان المود draft؛ ماشي مكان لمحتوى سري.
- المفاتيح العامة ماشي حماية بوحدها. الحماية هنا من grants وRLS. مفاتيح secret/service-role ممنوعة فالتطبيق.
- إعدادات تأكيد البريد وSMTP وredirect URLs كتحتاج مراجعة فمرحلة Auth؛ هاد السكريبت ما كيبدلهاش.
