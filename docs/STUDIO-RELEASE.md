# Craftly 1.3 — Studio & first-launch experience

## تحميل التطبيقين
- **craftly-explorer.apk**: تطبيق المستخدم.
- **craftly-studio.apk**: تطبيق الأدمن.

نفس مشروع Supabase ونفس الحسابات والمودات. ما خاص حتى SQL جديد أو تغيير إعدادات السيرفر.

## الجديد في هذه النسخة
- Studio جديد: إحصاءات حقيقية، أغلفة المودات، Published، عرض وحذف، تصفية حسب التصنيف، وترتيب Newest / Most downloaded / Top rated. عرض قائمة أو شبكة، و«عرض المزيد» محلياً كل 30 موداً.
- شريط التنقل العائم بخمسة عناصر باقٍ كما هو. داخل Studio كيبقى Account هو القسم النشط.
- فورم نشر ببطاقات ناعمة: اسم ووصف بعداد حروف، تصنيف، اقتراحات إصدار Minecraft مع إمكانية كتابة إصدار آخر، وتقييم المحرر.
- معاينة الغلاف المختار، واسم/نوع/حجم الملف، والتحقق المبكر من النوع والحجم. الحدود الأصلية محفوظة: غلاف 8 MiB، حزمة 50 MiB، اسم 3–80 حرفاً، وصف 15–5000 حرفاً.
- إزالة checkbox القديم. النص **“I have permission to distribute this content and have tested it in Minecraft.”** محفوظ، مع تأكيد مرئي مفعّل افتراضياً بلا نقر متكرر. هذا إقرار الناشر، وليس شهادة بأن Craftly فحص الترخيص أو جرّب المود.
- حالة نشر حقيقية على مراحل: تحقق، رفع الغلاف، رفع الحزمة، ثم إنشاء سجل المود. ليست نسبة بايتات وهمية. عند الفشل يبقى الفورم والملفات لإعادة المحاولة، ويجري تنظيف الملفات المكتملة قدر الإمكان.
- شاشة بداية سينمائية بنفسجية لمدة تقارب ثانيتين، وشاشة ترحيب فيها دخول بالبريد/إنشاء حساب/استكشاف أولاً. الفن مضمّن ومحسّن بصيغة WebP، ولا يحتاج تحميل صورة خارجية عند الإقلاع.
- الترحيب يظهر لأول مرة فقط إذا ما كانتش جلسة محفوظة. بعد الدخول كتستعمل الجلسة الحقيقية المحفوظة والمجددة بواسطة Supabase؛ علامة الترحيب المحلية لا تمنح دخولاً أو صلاحيات. الحسابات التي سبق لها الدخول تتجاوز الترحيب حتى إن غابت علامته المحلية. بعد الخروج المتعمد يمكن الدخول من Account.
- استرجاع الجلسة والكتالوج بالتوازي مع splash للمستخدم العائد، بدون انتظار الشبكة لإخفاء شاشة البداية.
- الإنجليزية والعربية RTL، مع دعم تقليل الحركة وتحسين شاشة الدخول الحالية. لا أزرار Google/Apple وهمية أو مزودات OAuth غير مهيأة.

## الأداء والبيانات
- التنقل والفلاتر والترتيب لا يعيدون تحميل الكتالوج. النشر والحذف يحدثان القائمة المحلية مباشرة بعد نجاح Supabase.
- ذاكرة طلبات مؤقتة مع تجميع الطلبات المتزامنة: الكتالوج والبروفايل 60 ثانية، المفضلة وسجل الطلبات 30 ثانية. سجلات المستخدم منفصلة حسب هويته، وتُلغى الذاكرة عند تغييرات الحساب والبيانات. لا تُخزّن نتائج الأدوار أو روابط الملفات الموقّعة على القرص بهذا الكاش.
- تاريخ طلبات التنزيل يتحمل عند الحاجة بدل تحميله في بداية كل دخول. التحديث اليدوي من Settings يتجاوز كاش الكتالوج.
- صور Studio كسولة التحميل بأبعاد ثابتة، ومعاينات الملفات تُحرر عند الإغلاق. الأغلفة الجديدة لها Cache-Control ليوم واحد وأسماء UUID فريدة. Android يستعمل HTTP cache الافتراضي.
- الشاشات الأخرى وSupabase وصلاحيات RLS ومدير التنزيلات وطلب الاستيراد إلى Minecraft محفوظة.

## التحقق والحدود
- اختبارات الوحدة/API/SQL-RLS/الملفات/التنزيل والكاش: 11 ناجحة.
- اختبارات متصفح مع Supabase محاكى: splash والترحيب، تسجيل الدخول واستعادة الجلسة حتى بدون علامة الترحيب، عدم تحميل الكتالوج في شاشة الترحيب، معاينة الملفات، إقرار مفعّل بلا checkbox، رفع يفشل ثم ينظف ويُعاد بنجاح، فلاتر وترتيب/عرض Studio، عدم إعادة تحميل البيانات أثناء التنقل، خمس وجهات، RTL، المفضلة والتقييم والتنزيل والحذف وتأكيد البريد.
- GitHub Actions يعيد الاختبارات ويبني التطبيقين، مع فحص قراءة فقط لـSupabase الحقيقي. لا تُستخدم بيانات دخول المالك ولا تُرفع ملفات اختبار إلى مخزنه الحقيقي.
- يبقى اختبار رفع مود حقيقي واستيراده في Minecraft والتوقف/الاستئناف الأصلي على الهاتف ضرورياً. لا ادعاء باختبار جهاز فعلي.
- أبقِ التطبيق مفتوحاً أثناء الرفع والتنزيل. لا إضافة لخدمة تنزيل بالخلفية أو استئناف رفع دائم بعد قتل التطبيق.
- APKs تجريبية debug، الإصدار **1.3.0 / code 4**، Android 8+ مع Android System WebView محدث. إذا اختلف التوقيع ورفض الهاتف التحديث، قد تحتاج حذف النسخة القديمة؛ احفظ الملفات المهمة أولاً لأن ذلك يمسح الجلسة والإعدادات والملفات المحلية. حسابك ومودات Supabase لا تُحذف.
- Google Play يحتاج توقيع release ثابت وسياسة خصوصية واختبارات الأجهزة. موارد خطة Supabase المجانية مازالت محدودة.
